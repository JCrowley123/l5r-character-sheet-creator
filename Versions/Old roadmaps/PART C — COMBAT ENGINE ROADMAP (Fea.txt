Senior Software Engineer + Senior QA Edition
For Claude code to analyse before implementing
GLOBAL RULES (Apply to ALL Features)
Architecture Constraints

* Follow the sheet’s architecture exactly:
   * Static reference tables
   * Row factories
   * Hidden‑input DOM state (DOM‑as‑model)
   * Pure calculation functions
   * Thin orchestration wrappers
   * Explicit save/load
   * Migration‑safe behaviour
* Never modify frozen functions:
   * `rollDicePool`
   * `showRollResult`
   * `collectData`
   * `applyData`
   * Ten Dice Rule
* Never modify Part B behaviour
* Never change save/load shape
* All new fields must NOT use `f_` prefix   (to avoid save pollution)
* All features must be removable without migration
* All features must be isolated decorators

Testing Requirements (ALL Features)
Each feature must deliver:

1. Validation Test Suite   Tests the feature’s logic, UI, DOM behaviour, negative scope, determinism.
2. Regression Test Matrix   Ensures Part B behaviour remains unchanged.
3. Automated Test Harness Prompt   A Claude‑ready harness that can be run on:
   * Part B baseline
   * Version A
4. Cross‑Version Signature   Ensures save/load, attack dice, damage dice, TN, and row‑level values remain identical across builds.



PHASE STRUCTURE (ALL FEATURES)
Each feature must be implemented in four phases:
Phase 1 — Static Data + Row Factories

* Add new static tables
* Extend row factories
* Add hidden inputs
* Add default values
* Add migration‑safe load behaviour

Phase 2 — Pure Functions

* Add pure calculation functions
* Add context constructors
* Add modifiers (TN, dice, damage, etc.)
* Add validation logic

Phase 3 — Orchestration Decorators

* Hook into roll flows
* Modify DOM state
* Apply modifiers
* Respect once‑per‑roll rules
* Respect negative scope rules

Phase 4 — Testing

* Feature harness
* Regression matrix
* Cross‑version signature
* Automated harness prompt

Claude must follow this structure for every feature.
